      What this simulator models
      • C is translated to JavaScript and run on a virtual clock. SysCtlDelay, timers, UART baud rate and ADC conversions take the time they would on the board. Plain statements are free, so tight loops are only approximately timed.
      • DriverLib calls for system control, GPIO (with interrupts), Timer0-7, SysTick, UART0, I2C0, SSI0, ADC0/1 (processor trigger), PWM0 and NVIC.
      • Faults are enforced: using a peripheral before SysCtlPeripheralEnable is a hard fault, a missing TimerIntClear is an interrupt storm, and the user switches read as pressed unless you enable the weak pull-ups.
      • Parts: tick any of the on-board items or add-on parts in Components (4x4 keypad, relay, LED bar, RGB LED, 7-segment display, buzzer, DC motor, servo, stepper, DIP switches, push buttons) and wire them to any pins. Parts read the pin signals, so GPIO, PWM and timer-driven outputs all work. Outputs of one PWM generator share a period, as on the chip.
      • Register-level code works too: GPIO_PORTN_AHB->DATA, SYSCTL->RCGCGPIO, TIMER0_CTL_R, HWREG() and raw addresses such as *(volatile uint32_t *)0x400643FC, with NVIC, SysTick, and the PLL clock registers. Touching a peripheral with its clock off is a bus fault.
      • I2C0 (PB2 SCL, PB3 SDA, master mode, DriverLib or registers) and SSI0 (PA2 CLK, PA3 FSS, PA4 MOSI, PA5 MISO, SPI master, modes 0-3) run bit-accurately on a virtual wire at the programmed clock rate. Virtual devices on the bench answer them: temperature sensor, EEPROMs, LCD and OLED, 74HC595. The bus decoder lists every transaction (ACK/NACK, chip-select frames) and the analyzer draws SCL, SDA, CLK, MOSI and MISO. I2C1-3, SSI1-3 and slave modes are not simulated.
      • Not supported: pointer arithmetic such as *s++, structs, function pointers, DMA, Ethernet, USB, CAN. UARTprintf has no %f, like the real library. printf does.
      • Debugger: tick Debug build, then click a line number (or press F9) to set a breakpoint. Step over, into and out (F10, F11, Shift+F11) work across functions and interrupt handlers; the call stack marks handlers that interrupted main. Variables, watch expressions and every peripheral register can be inspected while stopped, and registers can be edited. Debug builds run somewhat slower.
      • Interrupt handlers are found by the vector-table name (GPIOJ_Handler, Timer0A_Handler, SysTick_Handler, UART0_Handler, I2C0_Handler, SSI0_Handler, ADC0SS3_Handler) or registered with IntRegister.
